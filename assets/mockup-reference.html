Work · Evals

An AI chief of staff that never hits Send

A scheduled agent drafts my email, books my work, and tracks every promise I make, while code makes sure it can never send, delete, or share. Dry runs on my real data found 28 failures that synthetic tests missed.

RolePM and builder
WhenOct 2026 to now
Built withClaude Code, MCP
MeasuresEvals
2-minute demoA note arrives, the agent books and drafts, the guardrail blocks a send. Recorded on synthetic data.

Problem

I'm a dual-degree student, a teaching assistant, and a consultant. Most of what lands on me starts as a blank page, and the promises I make live in meeting notes, email, and chats with no single place to see them.

The job: start every piece of work from a draft and keep every commitment in one place, without the agent ever acting on my behalf.

3 rolesschool, teaching, consulting

How it works

Everything deterministic (time zones, free slots, dedupe keys, edit ratios) is plain tested code, never the model.

4×runs a day in the cloud

My role

I decided: the problem and scope, "drafts, never sends," the switch from a block list to an allow list, outlines instead of drafts for graded coursework, the privacy boundaries, and where to trade recall for precision.

AI built: nearly all code, prompts, and tests, to my specs and under my review. I ran every real-data dry run and hand-labeled the eval sets.

AI nativedirecting agents is the skill

Decisions and trade-offs

Safety in code, not the prompt. A hook blocks anything not on an allow list, including tools on connectors added later. The cost: some useful actions, like deleting a stale event, still need me.

Precision or recall depends on what a mistake costs. A missed promise breaks a commitment, so promise detection favors recall. A false style rule changes every future draft, so the edit learner favors precision.

Real data over synthetic sets. Every feature ran in dry-run mode on my real accounts before it could write anything.

0sends, deletes, or shares possible

Before and after

Block list missed a new "clear all" tool→Allow list blocks unknown tools
Promise detection: 59% precision, a student name leaked→100% precision, 7/7 recall, no leaks
Edit learner invented 1 false rule→0 false rules (4 of 5 habits found)
59% → 100%promise detection precision

Results

  • 5 weeks live, 111 commitments tracked across three parts of my life.
  • 28 real failures found by dry runs; synthetic evals caught none.
  • A 42-case prompt-injection set: 19 attacks stopped by the guardrail alone.
  • Pending: light-edit rate, on-time closure rate, and the model-layer injection score (December).
42injection cases, results in Dec

If I were the PM at a lab

I'd ship agent tool permissions as default-deny, with a dry-run mode on by default, and make "run it on real data without writing" a release gate. Synthetic evals told me everything was fine; real data found 28 problems.

Release gatereal-data dry run before writes
